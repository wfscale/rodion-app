# «Твой рост» — контекст проекта

Персональное приложение под одного человека (Родион, 18 лет, продюсер экспертов).
Не продукт для рынка. Единственная метрика успеха: **сколько рассылок сделано
сегодня**. Всё остальное в приложении — фон, обслуживающий это число.

**Стек:** Next.js 14 (App Router) · TypeScript strict · Tailwind · Supabase · Framer Motion.
Данные — Supabase (Postgres + RLS). Хостинг — Vercel. PWA с push.

---

## 1. Главный принцип

Рассылки решают. Остальное — фон.

Из него следует всё остальное в коде:

- одна рассылка = **8 XP**, вся дисциплина за день (6 привычек) = 6 XP;
- закрытие эксперта = 1000 XP — на три порядка больше привычки;
- задачи дня **не дают XP вообще**: иначе их можно было бы «выполнить» вместо рассылок;
- счётчик рассылок на главной набран 96px, у остальных блоков — 14–16px.

Если предлагаемая фича не увеличивает число рассылок — её не должно быть.

## 2. Портрет пользователя

Работает рывками, легко теряет мотивацию, чувствителен к геймификации,
не любит объёмные списки задач (пугают заранее). Ключевые находки, встроенные
в продукт:

- **Ровное число.** 22 рассылки читаются как брошенная работа, 25 — как
  законченная. Отсюда `lib/round.ts`: приложение всегда показывает ближайшую
  ровную цель. Правило: ближайшая пятёрка, но если до неё один шаг — цель
  растягивается до десятка (22 → «ещё 3», 24 → «ещё 6»).
- **Постепенное раскрытие.** Полный список из 20 уровней пугает. Видно только
  текущий блок из пяти, дальше туман (`revealCeiling` в `lib/xp.ts`).
- **Перевыполнение, а не выгорание.** Квота растёт сама от выполнения, вручную
  не задаётся. Сверх квоты — бонусы, но потолка нет и давления нет.

## 3. Дизайн-система

- **Монохром на почти чёрном** `#0A0A0A`. Цвет — только смысловой:
  `success #64FF8C`, `danger #FF6B6B`, `warn #FFD166`. Акцент интерфейса —
  CSS-переменная `--accent` (перк 17-го уровня, `lib/accent.ts`).
- **Стекло** — базовая поверхность: `.glass` (rgba(255,255,255,0.06) + blur 16px
  + светлая рамка, радиус 20px). Непрозрачных карточек в приложении нет.
  Вложенный `backdrop-filter` в Safari iOS схлопывается в белый прямоугольник —
  не вкладывать `.glass` в `.glass`.
- **Шрифт** Manrope, минимальный размер интерфейса 14px, поля ввода **строго 16px**
  (иначе iOS Safari зумит страницу при фокусе).
- **Тап-цели минимум 44px** по высоте — везде, без исключений.
- **Анимации** — framer-motion, 0.2–0.35s, easing `[0.22, 1, 0.36, 1]`.
  Анимация означает событие; если она играет при каждой отрисовке, она
  обесценивается (`initial={false}` там, где это просто состояние).
- **Мобильный приоритет.** 375px — расчётная ширина. Горизонтальный скролл
  страницы запрещён; широкие таблицы и карты скроллятся внутри своего контейнера.

## 4. Структура

```
app/(app)/          авторизованная часть: главная, outreach, progress, notes, settings, project
components/         дизайн-система (ui.tsx, GlassCard, BottomSheet) + блоки экранов
lib/                вся логика без React — сюда же пишутся тесты
supabase/*.sql      схема и миграции, каждая идемпотентная
scripts/verify.ts   352 проверки чистой логики, без базы
scripts/smoke.ts    сквозные проверки на живой базе
```

**Правило:** любая логика, которую можно посчитать без DOM, живёт в `lib/` и
покрывается `verify.ts`. Компоненты только рисуют.

## 5. Ключевые модули `lib/`

| Файл | За что отвечает |
| --- | --- |
| `xp.ts` | 20 уровней, пороги, разблокировки, ключи идемпотентности |
| `round.ts` | механика ровного числа и вех |
| `quota.ts` | прогрессивная дневная квота (+3 за каждые 3 закрытых дня, потолок 30) |
| `gamification.ts` | каскад событий на действие: XP, тосты, оверлеи |
| `followup.ts` | каскад касаний 1 → 3 → 7 → 15 → 30 дней |
| `reminders.ts` | напоминания с датой и временем |
| `offer-patterns.ts` | разбор офферов: что общего у текстов, на которые отвечают |
| `insights.ts` | тепловая карта, приоритет, часы отклика, достижения, разбор воронки |
| `outreach-filter.ts` | поиск и фильтры по списку рассылок |
| `notes-stats.ts` | цепочка заметок, воскрешение старых записей |

| `chart.ts` | шкала и сглаживание кривой графика |

## 6. Инварианты, которые нельзя нарушать

1. **Логический день кончается в 4:00.** Отбой в 1:00 и задача «лёг до 1:00»
   несовместимы с календарными сутками. Везде `getLogicalDate()`, никогда
   `new Date().toISOString().slice(0,10)`.
2. **XP нельзя нафармить.** Начисление только через SQL `award_xp(amount, reason, once_key)`.
   `once_key` уникален на пользователя. Новое начисление = новый ключ в `onceKey`.
   «Ответил» и «Ответил — отказ» делят **один** ключ: ответ человека был один.
3. **Уровни в `lib/xp.ts` и SQL `level_for_xp()` обязаны совпадать.** Меняешь
   пороги — правь обе стороны одной миграцией и пересчитывай `profiles.level`.
4. **Пороги уже взятых уровней не понижаются и не повышаются.** Это обнуляет
   доверие к шкале. Первые шесть порогов заморожены навсегда.
5. **Статусы воронки:** `not_sent, sent, read, replied, replied_no, blocked, call, closed`.
   «Ответил — отказ» **считается ответом** во всей статистике и подсвечивается
   красным. Статуса «Отказ» больше нет — любые старые значения приводит
   `normalizeStatus()`.
6. **Закрытых дверей без комнаты не бывает.** Каждый уровень открывает
   реально работающий раздел или правило игры. Заглушка «скоро» запрещена.
7. **Свободный текст вместо справочников.** Ниша — обычная строка. `<select>`
   с фиксированным списком ниш в приложении запрещён.
8. **Ошибки сохранения не теряются молча.** Данные — смысл приложения.
9. **RLS на всех таблицах**, доступ строго к своим строкам. `refresh_token`
   Google закрыт колоночными грантами — браузер его не видит никогда.

## 7. Геймификация: как она устроена

- **Квота** растёт сама: каждые 3 закрытых дня +3, потолок 30. Вручную не задаётся.
- **Каскад события** (`gamification.ts`) возвращает список событий, а не рисует:
  XP → профиль → оверлей → **ровно один тост**, самый значимый. Несколько
  тостов подряд превращают экран в фейерверк и перестают что-либо значить.
- **Полноэкранные оверлеи** — только первое событие каждого типа за всю жизнь
  (первый ответ, первый созвон, первое закрытие) и закрытие квоты.
- **Лестница из 20 уровней** с туманом. Взял уровень, кратный пяти, — туман
  отступил ещё на пять, и об этом сообщает оверлей повышения.
- **Вехи** каждые 25 рассылок за всё время: +150 XP, не сгорают вместе с днём.
- **Ровное число** — единственная цель, которая никогда не кончается: квота →
  ровный счёт дня → ровный счёт за всё время.

## 8. Работа с базой

- Схема: `supabase/schema.sql`, дальше миграции `migration-v2…v5.sql`.
- Каждый скрипт **идемпотентный**: запуск дважды не должен ничего сломать.
- Новая таблица = таблица + индекс + `enable row level security` + четыре
  политики + триггер `touch_updated_at`.
- Приложение обязано пережить непрогнанную миграцию: см. `remindersReady` —
  если таблицы нет, раздел показывает спокойное объяснение, а не белый экран.

## 9. Как проверять работу

```bash
npm run verify   # 352 проверки чистой логики, база не нужна
npm run lint
npx tsc --noEmit
npm run build
npm run smoke    # сквозные проверки на живой базе (нужен .env.local)
```

**Обязательный порядок для любой правки:** `verify` → `lint` → `tsc` → `build`.
Все четыре должны быть зелёными. Не «скорее всего пройдёт» — запусти и посмотри.

## 10. Требования к качеству работы

Это личный инструмент, который человек открывает каждый день. Сломанный экран
здесь стоит дороже, чем в обычном продукте: он ломает не сценарий, а привычку.

Поэтому:

- **Проверяй себя до тех пор, пока не будешь уверен на 1000%.** Прогнал тесты —
  прогони ещё раз после последней правки. Собрал — открой и подумай, что могло
  сломаться рядом.
- **Новая логика без теста в `verify.ts` не считается сделанной.**
- **Читай соседний код перед тем, как писать свой.** Плотность комментариев,
  именование, порядок блоков должны совпадать с окружением. Комментарий
  объясняет *почему*, а не *что* — «что» видно из кода.
- **Каждая деталь обязана быть обоснована.** Если не можешь объяснить, зачем
  элемент на экране, — его там быть не должно.
- **Ничего не ломай ради нового.** Пороги, ключи XP, статусы — это накопленная
  история пользователя, а не константы.
- **Проверь на 375px.** Если что-то вылезает за край — это баг, а не мелочь.
- **Тексты — на языке пользователя,** короткие, без канцелярита и без
  восклицательных знаков через слово. Оба словаря (`ru`, `en`) обязаны иметь
  одинаковый набор ключей: `verify.ts` это проверяет.

## 11. Чего делать нельзя

- Добавлять XP за действия, не ведущие к деньгам.
- Показывать пользователю полный список уровней или всё, что откроется.
- Вводить `<select>` со справочником ниш.
- Делать фичу-заглушку за закрытым уровнем.
- Менять тексты «трезвого режима» (`sober` в словарях) — они написаны дословно
  и работают именно в таком виде.
- Хранить время напоминаний в UTC: `due_at` — локальная строка
  `YYYY-MM-DDTHH:mm`, чтобы «14:00» означало 14:00 на тех часах, на которые
  человек смотрит.
- Прятать ошибку сохранения.
